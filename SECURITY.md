# Security

## Reporting a vulnerability

Report privately through GitHub: open the Security tab of this repository and choose "Report a vulnerability". Do not open a public issue for anything that could be exploited before a fix ships.

Include what you can of the following. A proof of concept is welcome but not required.

- The command or tool involved, such as `nodloop guard`, `nodloop mcp`, `nodloop-server serve`, an SDK or a plugin skill
- The version from the release tag or the commit hash
- Steps to reproduce and the impact you expect

You will get an acknowledgement within 7 days and a fix or a decision within 30 days. Credit goes in the release notes unless you ask otherwise.

## Scope

nodloop runs locally unless you start `nodloop-server serve`. These are the surfaces worth attention.

| Surface | What it does | What is in scope |
|---|---|---|
| `nodloop guard` | Reads Claude Code hook input on stdin and blocks calls that match a veto. `guard install` and `guard uninstall` rewrite `~/.claude/settings.json` after writing a `.bak` backup | A veto file is trusted configuration, so a malicious veto file the user installed is not a vulnerability. A way for a tool call to bypass a matching veto is. So is a change to `settings.json` beyond the nodloop hook |
| `nodloop mcp` | Serves the tools of runs, verdicts and knowledge on stdio to the MCP client that started it. The tool `records` pages the raw records and the guard log of the home, with free text only when the call asks for content. Approving a judgment with a veto writes an approved veto file under `~/.claude/nodloop` that the guard then loads. Every call that decides records an agent proposal and changes nothing, except `intervene` once the person accepts the one confirm form it sends to a client that shows forms, which names the action and its target and is used once. The plugin starts `nodloop mcp --agent`, which serves no `approve`, `reaffirm` or `approve_compaction` and records every verdict as the session's | The client is trusted, and a host hook that accepts forms on its own, such as a Claude Code Elicitation hook, is the user's choice. Path traversal or command execution through tool arguments is in scope, and so is a status change from a call over stdio without an accepted form, an answer to a form the server never sent or sent for another payload, a tool of the agent server that decides without the form, or a record written under the name `nodloop` |
| `nodloop-server serve` | Serves the MCP tools over streamable HTTP to clients with a bearer key. config.json keeps only the SHA-256 of each key. A key names a tenant and a role, and only an approver key added with `--person` decides, under its name. Every other key records a proposal. `key add --person` runs only when stdin and stdout are an interactive terminal and no variable of an agent session such as `CLAUDECODE` is set, the proof the commands that decide take. `GET /v1/records/{kind}` pages the raw records of the tenant of a reviewer or approver key in their published schema, with outputs, reasons, notes, errors that may quote them, lesson content and the paths of rules files, designated files and the guard log only when the request asks `content=true`. The `dir` label, an absolute path outside a repository, goes in every page since a scope names it. `POST /v1/interventions` takes one intervention of a reviewer or approver key, which decides only under an approver key added with `--person` and records a proposal under every other key | A request without a valid key reaching a tool, a report or a records page, a key reading or writing another tenant's records, a role calling a tool outside it or a producer key reading a report or a records page, free text in a page that did not ask for it, a status change under a key without `--person`, through `/mcp` or `POST /v1/interventions` alike, a key that proves a person added from an agent session or a script, an approval or a verdict with proof `key` recorded under a name other than the holder of the key, or a verdict or an outcome recorded under the name `nodloop`, which only the capture of a session writes, is in scope. `/healthz` answers without a key and reveals nothing but that the server runs, and `/v1/openapi.json` answers without a key and holds only the routes and the published schemas. Serving on a public address without TLS in front is a deployment choice, not a vulnerability |
| `nodloop export package` | Writes the raw records of the record directory and the guard log of the home as `datapackage.json` and one CSV per kind into the folder `--out` names, which must be missing or an empty real folder. The folder gets mode 0700 and every file mode 0600, and no file is opened that already exists. Outputs, reasons, notes, errors that may quote them, lesson content and the paths of rules files, designated files and the guard log go only with `--with-content`. The `dir` label, an absolute path outside a repository, goes in every export since a scope names it. Cells are written as recorded for table readers such as DuckDB or pandas, so a spreadsheet may read a cell that starts with `=` as a formula | A write outside the folder, through a link, or into a folder that holds files, free text without `--with-content`, or `hmac.key`, config.json or a header value in an export is in scope |
| Commands that decide | `knowledge approve`, `retire`, `reaffirm`, `approve-compaction`, `intervene`, `knowledge import`, `config approver`, `config session_mode` with a value, `llm set`, `llm unset`, `classifier set` and `unset` of the judge and the reaction point, `anchor add` and `anchor remove` decide only when stdin and stdout are an interactive terminal and no variable of an agent session is set: `CLAUDECODE` of Claude Code, `CODEX_THREAD_ID` of Codex, `CURSOR_AGENT` of Cursor or `COPILOT_AGENT_SESSION_ID` of Copilot CLI. Otherwise the first five record a proposal and the others fail and change nothing | A way for a command run by an agent session to change a status, the saved name, the session mode, the model backend or the endpoint of the judge or the reaction point without a person is in scope. A process of the same user that writes the record files itself or runs the command under a pseudo terminal it made is not, since nothing in the process can tell it from the person |
| Classifier endpoints | `classifier set <point> --url` saves one endpoint per decision point and the name of an env var holding its key. Drafts and the user's message are sent to the endpoint of their point. Once `knowledge curate` runs, the endpoint of the judge point is sent each change it judges with the anchor lines of its place, which hold the lessons you approved there and the text of the files you designate and of the rules files your sessions there loaded, and your own words on the runs the change cites. A URL with a user or a password is refused and a redirect fails the call. A classify trace keeps the status of an error answer without its body and no reason a member gave | A key written to config.json, a request to an endpoint no point names, following a redirect, text of the state in a classify trace of the reaction or judge point, or an answer body that crashes or exhausts the process is in scope. What an endpoint you configured does with the text is not |
| Conversation hooks | `nodloop hook start` adds approved items again after a compaction or a clear and on every start of a host without a prompt hook, `nodloop hook subagent` adds them to a subagent, `nodloop hook prompt` adds approved items to a prompt and `nodloop hook stop` records the last answer as a run with secrets redacted and starts `nodloop session capture` on the transcript Claude Code names, or with no transcript on Codex. The capture reads only the transcript Claude Code keeps for the session, `<session id>.jsonl` in a project folder under `projects` of `~/.claude` or `CLAUDE_CONFIG_DIR`, refuses any other path before it reads or records anything, and reads that file from where its previous pass ended, never copies it, and keeps of a message only its redacted words cut at 500 runes as the reason of a verdict it is sure of and an HMAC in its classify trace. The stop pushes at most one question of curate per session at the end of an answer, beside the proposals the person asked for through the manual path, and the answer to a question is recorded only from the person's own input: the label picked in an AskUserQuestion call whose header names the question, counted only as the result of that call, or the first word of the next message, both read by the capture from the transcript in every mode but off. The prompt hook reads that word only to keep it from being judged and records no answer, since any process can pipe a prompt into a hook. A question keeps only an HMAC of its text. `nodloop hook instructions` reads each CLAUDE.md and rules file Claude Code reports loading and records its path with an HMAC of its content, leaving out `approved.md` of the record directory and auto memory. The same hooks run under Codex, Cursor and Copilot CLI with `--host` | A way for an answer or a label to make a hook write outside the record directory, block a prompt or a stop, keep a secret the redaction should remove or keep the text of a rules file is in scope, and so is a transcript line that makes the capture read another file, write outside the record directory or keep the text of a tool result, and any way for a model, a tool result or another program to record an answer the person did not give, or a block the host or an IDE adds to a message, such as a reminder or a selection, read as the person's words. So is a hook input or a `session capture` call that records an answer or a verdict of reviewer `nodloop` from a file the host does not keep for the session. A process of the same user that writes into the folder where the host keeps its transcripts is not, as with the terminal, since the capture reads what the host would hand it |
| Input files | Reads files named by `run record --output`, `knowledge import --file`, `feedback add --edited`, `intervene --payload` and `export package --since`, and the files `anchor add` designates, which `nodloop anchor` reads to keep an HMAC of their content | A crafted file that escapes its path or executes anything is in scope |
| Records and config | Writes runs and every other trace, feedback, outcomes and knowledge to the record directory and reads `~/.nodloop/config.json`. With a retention set, `nodloop records prune`, the daily prune after a run and the prune of nodloop-server remove old runs and keep their cutoff in `prune.json`, and first append the counts of each closed cycle of curate as a `rollup` trace. The daily consolidate and the OTLP export keep their marks in `consolidate.json` and `export.json`, and `knowledge curate` keeps its cycle, knobs and the questions due in `curate.json` with a `decide` trace per change it sorted, whose diff it keeps as an HMAC. The captures take turns on `capture.lock` and keep their offsets in `capture` traces. `hmac.key`, mode 0600, keys every HMAC nodloop keeps in place of a text: your message and the anchor at a decision point, the text of a question or a notice of the stop, and a rules file or a designated file in the instructions hook and `nodloop anchor`, so no trace holds that text | A write outside those paths is in scope, and so is a prune that removes a run a verdict, an outcome or a knowledge version cites, a classify trace of the reaction or judge point, an `instructions` trace or an `anchor` trace that holds the text it hashes, or `hmac.key` in an export, a record or a log |
| OTLP export | `nodloop export otel` posts records as spans and evaluations as log records to the endpoint and with the headers the user names. Only `nodloop otel set` makes the stop hook, `nodloop mcp`, `knowledge extract`, `knowledge consolidate`, `knowledge curate` and `session capture` start `export otel --pending` on their own, so a standard `OTEL_*` variable set for another tool never starts an export, and the command reads those variables only when neither a flag nor config.json names an endpoint. config.json keeps the endpoint and the name of the variable that holds the headers, never a header value, and refuses an endpoint with a user, a password, a query or a fragment. Without `--content` a span carries ids, times, durations, the producer, the session id, the plugin version, models, token counts and cost, the subject, labels such as `repo` and `dir`, which is an absolute path outside a repository, the ids of the items with the holdout arm, unit and share of a run, where the unit is the `holdout_key` a producer passed, verdict and outcome labels, reason codes, reviewer and approver names with the proof and authority behind them, the extract conclusion, the classify point, the compaction id, the enums of questions, answers, interventions and curate decisions such as kind, source, round, tier, rule, bin, choice, overturn, retire reason and a knob with its value and the one before, with their cycle and draw probability, the model, effort, outcome and share of each judge member, and the error type of a failed run or model call. With it, run outputs, verdict reasons and edited outputs, outcome notes and causes, candidate text and the error of a failed run or model call go too. Run outputs and what an inferred reviewer records pass the secret redaction when they are recorded, what a named reviewer writes is kept as written, and no prompt text is stored to send. A redirect fails the export, and an error names the endpoint without its password or query | Sending to an endpoint nobody configured, starting on its own without `otel` in config.json, following a redirect, sending text without `--content`, or writing a header value to stdout, config.json or a record is in scope |
| Model calls | `llm probe`, `knowledge compact`, `knowledge check`, `knowledge check --replay`, `knowledge extract`, `knowledge replay`, `knowledge consolidate`, `knowledge curate` and `session capture` run `claude -p`, or the binary `NODLOOP_CLAUDE_BIN` names. The capture the stop hook starts sends each message you typed with the answer before it, cut at 4000 runes, and the text of the lessons that answer had in its context, to the endpoint of the reaction point first when one is set. `llm set chat` sends the same prompts instead to the Chat Completions endpoint it saves, with a key read from the env var it names. The stop hook starts `knowledge curate --daily` in a process of its own at most once a day, which drafts each correction no extraction read and judges each waiting lesson. When the judge of curate runs, each call sends the change, the anchor lines of its place, which hold the lessons you approved there and the text of each file you designate and of each rules file your sessions there loaded as it reads at the call, and your own words on the runs the change cites, which are the reasons of your verdicts with a proof and the redacted words the capture read, and its classify trace keeps only their HMAC. A base URL with a user, a password, a query or a fragment is refused, a redirect fails the call, an answer the schema refuses twice fails without quoting what it held, and an answer past 1 MiB or past the timeout fails it | A way for a record or model output to change that command line is in scope, and so is a key written to config.json or a log, or a request to an endpoint the config does not name |

`nodloop guard call`, the MCP tool `check_call` and `CheckCall` in Go return allow, block or ask for a tool call of another agent. A call that matches a veto of its producer and comes back allow is in scope.

The Python and TypeScript SDKs start a local `nodloop` binary or fetch the release of their version into `~/.nodloop/bin` and check it against `checksums.txt`, like the launcher below. A way to make them run another binary is in scope.

The `plugin/bin/nodloop` launcher downloads a release archive from this repository over HTTPS into `~/.nodloop/bin` and checks it against `checksums.txt`. It reads the version from `.claude-plugin/plugin.json`, else `.codex-plugin/plugin.json`, and refuses one with a slash or a dot segment. A way to make it fetch or run something else is in scope.

`checksums.txt` comes from the same release, so it shows an archive arrived whole, not who built it. Every archive also carries a build provenance attestation signed through GitHub Actions and an SPDX SBOM. `gh attestation verify nodloop_darwin_arm64.tar.gz --repo jeon-jihyeon/nodloop` checks that the archive was built by the release workflow of this repository from its tag.

Model output is untrusted. A proposed knowledge item reaches a prompt only once a person approves it, which only a terminal of their own, a server key they hold, a form they accept or their own answer to a question of the stop proves. Once the person says yes to ending the shadow of curate, nodloop also approves a change its rules and judge find the person's recorded decisions already settle, and the person can undo it. That gate stops a model deciding by accident or on an instruction it read. It is a design property, not a security boundary. Do not rely on it to contain hostile model output.

## Supported versions

Only the latest release receives fixes.
